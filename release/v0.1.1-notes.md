# sedra-rusty v0.1.1: release notes

> Published as the GitHub release text of `sedra-v0.1.1`, without this note. **[release day]** values are filled in
> when the tag is made.

## What changed since 0.1.0

A maintenance release. **The node behaves exactly as 0.1.0**: same consensus rules as Sedra's Go node `sedrad` v2.0.0,
no new rules, nothing to do for anyone running 0.1.0 except that `--version` now prints `0.1.1`.

- The README and the release docs now show the release: status, a "Run a node" section, the result of the seven-day
  comparison, and the two-machine rebuild of 0.1.0.
- The reproducible build script `build-in-docker.sh` no longer ends with exit code 1. Its last step runs
  `kaspad --version`, which exits with 1 after printing (upstream rusty-kaspa behaviour); the build itself was always
  complete.
- The release is `0.1.1` in `kaspad --version`.

Everything else, including the evidence, is unchanged from the
[0.1.0 release](https://github.com/necatgit/sedra-rusty/releases/tag/sedra-v0.1.0).

## Verify before you run it

1. **Checksum:** compare the archive with `SHA256SUMS`.
2. **Signature:** the tag `sedra-v0.1.1` is signed by Nec (fingerprint `SHA256:Eh/4CtYZPvHjYldtNexGX4RLCsz/Mi5MsBZDLKTRvUc`,
   published at <https://puddlepool.com/keys.html>):
   `git -c gpg.ssh.allowedSignersFile=allowed_signers verify-tag sedra-v0.1.1`
3. **Rebuild:** `docs/RELEASE.md` explains how to get the same bytes yourself. Independent rebuilds are welcome as a
   comment on the release issue.

## Running it

Linux amd64; see "Run a node" in the README. Mainnet is the default; ports 22110 (RPC, never expose it) and
22111 (P2P). For wallets, pools and explorers start it with `--utxoindex`.

## Reporting problems

Bugs: GitHub issues. Security problems: privately, as described in `SECURITY.md`.
