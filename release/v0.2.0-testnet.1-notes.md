## What this is

The node release for Sedra's **public merged-mining testnet** ([SIP-0003](https://github.com/necatgit/sedra-project/blob/main/proposals/SIP-0003-public-testnet.md)).
It runs on the test network `sedra-testnet-10` only, where merged mining with Kaspa testnet-10 is switched on in
public so that it can be watched and tested before anyone decides anything about Sedra mainnet.

**Testnet only. No effect on Sedra mainnet.**

- The binary **refuses to start without `--testnet`** (or `--devnet`, `--simnet`). It cannot run as a mainnet node by
  accident. For Sedra mainnet keep using [0.1.1](https://github.com/necatgit/sedra-rusty/releases/tag/sedra-v0.1.1).
- `sedra-testnet-10` has its own network name, genesis, ports (P2P 22211) and address prefix (`sedratest:`); nodes
  refuse peers from another network in the handshake. Mainnet rules in this code are unchanged (merged mining
  `never` on mainnet).
- Testnet coins have no value, now or later. Passing the testnet does not schedule anything on mainnet.

## What is in it

| | |
|---|---|
| Merged-mining activation | **DAA score 345,600** on `sedra-testnet-10` (about day 4 of a chain mined from genesis at one block per second) |
| Self-parent ban start | **DAA score 172,800** (2 x finality depth before activation, about day 2): from here a Sedra block whose own coinbase carries an `SDM1` commitment is invalid (SIP-0001 §4.5) |

| Base | everything in the mainnet releases 0.1.0 and 0.1.1 (both are ancestors of this release), including the security back-ports from later rusty-kaspa releases |
| Version | `kaspad --version` = `0.2.0-testnet.1 (rusty-kaspa v1.0.1, commit 24511407f157)`; the P2P user agent stays `kaspad:1.0.1` |
| Testnet tools | `contrib/testnet/`: native CPU miner, monitor, faucet script, systemd units, testnet Miningcore config (built from source with `contrib/testnet/build_tools.sh`; not in the archive) |

The scores count from genesis (DAA score 0), so they hold whenever the chain is started. How they were chosen:
[testnet/RUNBOOK.md](https://github.com/necatgit/sedra-project/blob/main/testnet/RUNBOOK.md) 3.1.

## Verify before you run it

1. **Checksum:** `sha256sum -c --ignore-missing SHA256SUMS` (the archive), then after `tar xzf` the same without
   `--ignore-missing` (archive and `kaspad`).
2. **Signature:** the tag `sedra-v0.2.0-testnet.1` is signed by Nec (fingerprint
   `SHA256:Eh/4CtYZPvHjYldtNexGX4RLCsz/Mi5MsBZDLKTRvUc`, published at <https://puddlepool.com/keys.html>), and the tag
   message carries the two checksums:
   `git -c gpg.ssh.allowedSignersFile=allowed_signers tag -v sedra-v0.2.0-testnet.1`
3. **Rebuild:** `docs/RELEASE.md` explains how to get the same bytes yourself. Independent rebuilds are welcome as a
   comment on the release issue.

## Running it

Linux amd64. Participant guide (node, wallet, native and merged mining, reports):
[testnet/GUIDE.md](https://github.com/necatgit/sedra-project/blob/main/testnet/GUIDE.md). Short form:

```
./kaspad --testnet --utxoindex --disable-upnp --nodnsseed --appdir=$HOME/sedra-testnet \
  --rpclisten=127.0.0.1:22210 --addpeer=<seed1>:22211 --addpeer=<seed2>:22211 --yes
```

Seed addresses and the testnet pool are announced at launch in
[sedra-project #13](https://github.com/necatgit/sedra-project/issues/13). (*2026-11-27:* seed1 is not published (it runs on the operator's home network); the pool address follows later; the public seed is `62.83.121.25:22211`.) Never use `--aux-pow-activation-override`
on the public testnet: your node would split off.

## Known limits

- **Linux amd64 only**; the binary is still called `kaspad`. The testnet tools are built from source.
- **Timing is approximate.** The ban start and the activation are DAA scores; "day 2" and "day 4" assume one block
  per second after the first 2,641 blocks (mined at genesis difficulty within minutes).
- **One chain, no reset built in.** If a consensus bug is found, the fix is a new testnet release (and the two-week
  clock restarts); the options are in RUNBOOK §6 (problems, reset). The test pauses on any failure.
- **Old Go nodes stop at the first merged-mined block.** That is expected and is one of the things the testnet shows
  (criterion 3).
- **Someone else could mine the same genesis.** The test chain starts from Sedra's existing testnet genesis (2021);
  anyone who mines a heavier chain from it could pull nodes onto theirs. The seeds are watched by the monitor; a
  takeover would be reported in #13 and handled as in RUNBOOK §6.
- **Kaspa testnet-10 could change its block format.** Then merged mining stops and native mining continues until a
  parent-decoder update (SIP-0001 §4.6).
- Not shown before launch: a pruning proof with merged-mined headers on a long chain, and pool payouts of both
  coins on the public network (the Kaspa TN10 wallet path was checked on a private chain).

## Reporting problems

Testnet reports and faucet requests: the "Testnet report" issue template in
[sedra-project](https://github.com/necatgit/sedra-project/issues/new/choose). Security problems in the node: privately,
as described in `SECURITY.md`.

## What this does NOT mean

- It does not launch the testnet; the launch date is announced separately.
- It is not a mainnet release and changes nothing on Sedra mainnet. No mainnet date is set.
- A passed testnet does not schedule merged mining on mainnet; that is decided with the Sedra team after the report.
- Testnet coins have no value. There is no reward, airdrop or allocation for taking part.
